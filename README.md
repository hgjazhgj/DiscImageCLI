# DVD 图片转 ISO

将 **8192 × 8192 PNG** 转为一个 DVD 盘面绘图 ISO，可同时加入目录中的文件：默认接受 1–8 张，标准通道合并接受 1–6 张，加宽通道合并接受 1–9 张。
默认每张图片按文件格式选择灰度或完整 RGB 载波，支持灰度、彩色及混排；多张图片按观看方向复用，转动或倾斜盘片时切换图案。
指定 `--color-range standard` 或 `--color-range wide` 即启用源项目的彩色动画通道合并，分别使用六载波标准范围或九载波加宽范围；不指定时不合并。
也可根据盘片配置和文件布局生成 **8192 × 8192 黑白可绘区域蒙版**。

程序使用统一的轨道定位与载波编码流程。灰度保留原始灰度比例，彩色保留 R、G、B 三个通道；
采样后按载波的圈排程、亮度增益和门限生成字节，再补偿 DVD 扰码。
`--no-gain` 可将所有灰度和彩色载波的增益固定为 1，默认仍使用各方案计算的增益。
位置周期补偿默认关闭；需要时在观看 JSON 中明确设置 `"chirp": true`。
程序只读本地图片、配置和随盘文件，输出 ISO 及参数 JSON，或 PNG 蒙版。
不联网、不查询或打开光驱、不读取盘片容量、不执行刻录。

程序假定输入符合下述约定，不额外校验输入参数、图片尺寸、路径或库调用的数据布局；这些约定均由使用者保证。
命令行保留 `add_argument` 中的类型、可选值及必填声明；不适用当前模式的参数直接忽略。
UDF 写入器保留名称编码、描述符字段长度和布局完整性检查，几何求解保留收敛保护，文件操作保留 I/O 错误处理。

## 安装

需要 Windows x64、64 位 Python 3.10+，以及 NumPy、Pillow：

```powershell
python -m pip install -r requirements.txt
```

不需要安装 Disc Image Studio、DiscDiffractStudio、.NET 或外部 ISO 制作工具。
离线安装时，可提前准备匹配目标 Python 和系统的 wheel 目录：

```powershell
python -m pip install --no-index --find-links .\wheels -r requirements.txt
```

项目文件放在同一目录，运行资源为：

| 文件 | 用途 |
|---|---|
| `dvd_image.py` | 命令行与配置读取、ISO/蒙版输出调度、读取保护、进度及参数 JSON |
| `dvd_disc.py` | 盘片配置类型、DVD 常量与扰码表、统一输出计划 |
| `dvd_geometry.py` | 完整盘片的轨道几何求解 |
| `dvd_kernel.py` | ctypes 与 DLL 封装；`PreparedKernel` 持有几何、图片和载波并生成批次 |
| `dvd_kernel.dll` | 合并后的轨道几何、采样与载波编码原生库 |
| `dvd_multiview.py` | 读取 PNG 和载波资源，统一准备图片、载波/增益/排程 profile |
| `dvd_carriers.py` | 根据观看参数合成字节串载波，计算光谱响应、白平衡及圈份额 |
| `dvd_chirp.py` | 启用周期补偿时，根据盘面位置和观看姿态准备周期变体、位置索引及载波字节串表 |
| `multiview-carriers.json` | 默认方案的字节串载波、周期及白平衡资源 |
| `efmplus-tables.json` | 动态载波合成使用的 EFMPlus 主编码表 |
| `udf.py` | 随盘目录的 UDF 2.01 文件系统 |

`dvd_disc.plan_output` 为 ISO 和蒙版提供同一份几何、可用容量及 UDF 绘图区计划。
生成 ISO 时，所有图片均由 `dvd_multiview.py` 的同一个构建流程准备，随后建立一个 `PreparedKernel`，供各批次共享。
该对象一次打包原生参数并保持指针背后的数组存活，不全局缓存每个几何对象。
批次编码与扇区解析接口集中在 `dvd_kernel.py`。

附带 DLL 可直接运行。开发时如需重编译，在项目目录的 **x64 Native Tools Command Prompt for VS 2022** 执行：

```bat
cl /nologo /O2 /fp:strict /MT /LD dvd_kernel.c /Fedvd_kernel.dll
```

`dvd_kernel.c` 包含几何、采样与载波编码，不通过 `#include` 包含其他 `.c` 文件。
DLL 导出 `dvd_generate`、`dvd_resolve_sector`，
只有 `dvd_kernel.dll` 需要作为原生运行库随程序提供。自定义观看载波由 Python 合成。

## 配置文件

[CMDR47G-CFMWM03-6865G.json](CMDR47G-CFMWM03-6865G.json) 是一个盘片配置示例。
`total_sectors` 为完整盘片的 **2048 字节用户数据扇区数**，用于几何标定，须为 16 的倍数。
程序不会从设备读取容量，也不会自动扣除保留扇区。

| 配置字段 | 默认值 | 含义 |
|---|---:|---|
| `total_sectors` | 必填 | 完整盘片容量，单位为 2048 字节扇区 |
| `inner_radius_mm` | 24 | 数据记录区内半径，mm |
| `outer_radius_mm` | 58 | 数据记录区外半径，mm |
| `channel_bit_nm` | 133.3 | 通道位长度，nm |
| `start_angle_deg` | 0 | 起始角度，0 向右，正角度逆时针 |
| `direction` | `cw` | 顺时针 `cw` 或逆时针 `ccw` |
| `pitch_linear` | 0 | 相对轨距一次系数 c1 |
| `pitch_quadratic` | 0 | 相对轨距二次系数 c2 |
| `pitch_cubic` | 0 | 相对轨距三次系数 c3 |
| `psn_offset` | `0x30000` | 物理扇区号偏移，整数或十六进制字符串，须为 16 的倍数 |

内外半径描述数据记录区，不是中心孔或盘片标称尺寸。配置使用 UTF-8 JSON。
`DvdOptions` 定义在 `dvd_disc.py`；命令行直接读取 JSON 并构造该配置对象。
三次轨距模型为 `x=(r-ri)/(ro-ri)`、`p(x)=p0*(1+c1*x+c2*x²+c3*x³)`；
`p0` 由容量、通道位长度和内外半径求解。已有完整四项 `a0+a1*x+a2*x²+a3*x³` 时，
填写 `c1=a1/a0`、`c2=a2/a0`、`c3=a3/a0`。三个系数全零即恒定轨距。

实际输出容量通过 `--bleed` 控制。缩短输出不会重算完整几何或缩放图片：
PNG 始终映射到配置的完整数据区外径，蒙版显示实际剩余可绘区域。

## 运行

| 命令行选项 | 含义 |
|---|---|
| `-i` / `--input` | PNG 路径，按顺序分配视图或合并通道；未合并 1–8 张，标准合并 1–6 张，加宽合并 1–9 张；可重复 `-i`；蒙版忽略 |
| `-o` / `--output` | 必填；`.iso` 生成镜像，`.png` 生成蒙版，扩展名不区分大小写 |
| `-c` / `--config` | 必填；盘片容量及物理参数 JSON |
| `-f` / `--files` | 递归加入 ISO 的本地目录；蒙版模式用于计算占用区域 |
| `-p` / `--position inner/outer` | 随盘文件位于内圈或外圈，默认 `inner`；无 `--files` 时忽略 |
| `-b` / `--bleed` | 可用容量比例，有限数值 `0 < bleed <= 1`，默认 `1` |
| `-l` / `--volume-label` | UDF 卷标，默认 `DVD_IMAGE`；仅带 `--files` 的 ISO 生效 |
| `-j` / `--jobs` | ISO 并行线程数，1–64；默认按逻辑 CPU 数选择，最多 64；蒙版忽略 |
| `--viewing` | 自定义观看参数 JSON 路径；按参考点、灯/眼位置和视图姿态计算载波，或直接指定 `target_u`；合并时按光学三元组指定；蒙版忽略 |
| `--color-range standard/wide` | 不指定时不合并；指定时必须提供 `standard` 或 `wide`：标准合并六载波、1–6 张，加宽合并九载波、1–9 张；蒙版忽略 |
| `--no-gain` | 默认关闭；指定后所有灰度及 RGB 载波增益均为 1，保留原圈份额和排程；蒙版忽略 |
| `--read-compatibility` | 实验性读取保护，默认关闭；应用于所有 ISO 绘图模式；PNG 蒙版忽略 |

完整帮助：`python dvd_image.py --help`。

```powershell
python dvd_image.py -i frame1.png frame2.png -o flip.iso -c my-disc.json
python dvd_image.py -i grayscale.png color.png -o mixed.iso -c my-disc.json
python dvd_image.py -i frame1.png -i frame2.png -o animation.iso -c my-disc.json
python dvd_image.py -i frame1.png frame2.png frame3.png -o standard.iso -c my-disc.json --color-range standard
python dvd_image.py -i frame1.png frame2.png frame3.png -o wide.iso -c my-disc.json --color-range wide
```

### 图片读取与采样

由使用者保证每张输入都是 **8192 × 8192 单帧 PNG**。程序直接读取原始像素，不校验尺寸，不裁剪或缩放。
图片中心对应盘心，边长覆盖配置的完整数据区外径；四角、中心不可绘区及随盘文件占用区不参与绘图。

| 输入格式 | 默认载波平面 |
|---|---|
| 1 位黑白（PNG 模式 `1`） | 一个灰度平面，最近邻采样 |
| 灰度、带透明度的灰度（`L`、`LA` 等） | 一个灰度平面，双线性采样 |
| RGB、RGBA、调色板等彩色格式 | R、G、B 三个平面，各通道双线性采样 |

分流依据图片格式，不检查像素颜色。默认 RGB 或调色板图片即使只含黑白、灰色像素，仍保留三个彩色通道；
RGB 图中局部灰色区域也使用 RGB 重建。透明度直接忽略，不与背景合成，透明像素保存的颜色仍参与编码。

采样依据图片模式，不扫描或判断像素内容：1 位黑白模式对轨道坐标四舍五入后取最近像素；
灰度与彩色各通道均先对原始 8 位数值做双线性插值，再按最近偶数规则取整为 8 位通道值；
即使整张灰度图仅含 0/255，也保持双线性采样。
最近邻路径的 Bayer 抖动锚点使用四舍五入后的像素坐标，双线性路径使用向下取整坐标。
基础灰度比例为 `g/255`，不做灰度 sRGB 线性化，点亮目标为 `(g/255) × gain`。

彩色在双线性采样及取整后，分别将 R、G、B 转为线性亮度，再乘各载波的白平衡增益。
插值发生在线性化之前；默认载波、标准／加宽通道合并、自定义观看及周期补偿均使用这套采样规则。

旧版单帧专用的 `measured`、`ladder` 方案已移除。`measured` 在整盘居中图像的 9 点方向存在 ±180° 方位角接缝，
使相邻区域采用色表两端的配方，产生明显色彩分界；`ladder` 在本次实盘使用中的效果不理想。

### 载波、亮度增益与按圈编码

未启用通道合并且未指定 `--viewing`、`--no-gain` 时，使用以下默认名义载波与增益，字符串方案保持固定名义周期；
默认单张、两张全灰度使用的 `92/B9` 单字节载波保持固定周期。全灰度输入的名义载波与增益为：

- 单张灰度图使用 `0x92`，占用全部轨道；按 `min(periods)/period_i` 计算，增益自然为 1。
- 两张灰度图使用 `0x92`、`0xB9`，周期分别为 16T、10⅔T，增益分别为 ⅔、1。
- 3–8 张灰度图使用默认动画字节串载波，增益同样为 `min(periods)/period_i`。

单张彩色图使用三个 RGB 字节串载波，周期约为 **16T、13.928809T、12.125733T**，
设计方向 `u = 0.288`，按光谱白平衡分配独立的 32 圈排程。
两张彩色图使用六个 RGB 载波，圈数为 `(3, 3, 7, 4, 5, 10)`。
其他多图及混排为每幅图选取方向，再为其灰度或 RGB 通道选取周期。

默认方案含彩色输入时，所有平面按光谱响应资源中的 `whiteNeed` 分配圈数，再用
`whiteNeed / 实际圈份额` 求增益，并以各平面的最大值归一化。
灰度平面仍使用 `(g/255) × gain`；彩色平面使用各自的线性 RGB 通道乘增益。
`u` 表示光源和观察方向在轨道切线上的分量，不是以度为单位的倾角；载波以 133.3 nm 通道位长度为参考。

指定 `--no-gain` 后，所有载波的实际 `gain` 统一为 1，适用于默认方案、标准／加宽通道合并、
自定义观看及周期补偿。灰度点亮目标改为 `g/255`，彩色点亮目标为线性化后的对应 RGB 通道值。
原有采样、RGB 线性化、载波周期、圈数和交错排程均保持原规则；彩色的白平衡圈份额仍保留，只取消剩余增益补偿，因而颜色和亮度可能变化。
这个开关不会把多图分走的圈位交回单张图片，也不使多图恢复单图的全圈亮度。
例如，两张默认灰度图仍使用各半圈位的 `92/B9`，但两者增益从 `2/3、1` 改为 `1、1`：

```powershell
python dvd_image.py -c CMDR47G-CFMWM03-6865G.json -i "D:\temp\g1.png" "D:\temp\g2.png" -o "D:\temp\g-no-gain.iso" --no-gain
```

各载波用自己的圈序号进行 **32 级位反转门限与基于原始像素的 4×4 有序抖动**。
字节串在同步帧处重新开始，占用必要的段首填充位置并裁剪尾部，然后补偿 DVD 扰码。
使用周期补偿时，在段首填充之后第一个实际载波字节的位置选定变体，保持到该载波组连续段结束或下一个同步帧；
跨越变体网格不会立即重启字节串。
批次、线程和随盘文件布局不会重置圈数或载波相位。

所有位置使用统一规则，不比较多张图的内容，不识别或合并共有区域，不按局部内容重分配轨道。
相同内容仍按各自视图的载波、增益和轨道份额写入。

### 可选通道合并

`--color-range` 同时启用通道合并并选择范围，采用 DiscDiffractStudio 彩色动画的通道选取规则，支持灰度、彩色及混排。
不指定该参数时不合并；指定时必须明确填写 `standard` 或 `wide`，没有缺省范围，也不接受 `None` 作为命令行取值。
程序不按输入数量自动切换。输入数量限制由使用者保证，代码不额外校验。
设图片数为 `N`、载波数为 `C`，载波 `k`（从 0 开始）取图片 `floor(k*N/C)` 的 `RGB[k%3]` 通道，
每三个相邻载波构成一个光学 RGB 视图，白平衡、观看方向和周期补偿均按这些三元组计算。

| 范围 | 输入数量 | 载波与排程 |
|---|---|---|
| 不指定参数 | **1–8 张** | 不合并；每张灰度图一个载波，每张彩色图三个载波 |
| `standard`（标准） | **1–6 张** | `C=6`，周期 `16 / 2^(k/5)`，从 16T 到 8T；两个光学视图，名义 `u` 为 `0.288`、`0.288*2^(3/5)`（按实际通道位长度换算），共 32 圈 |
| `wide`（加宽） | **1–9 张** | `C=9`，源宽方案周期 `20.4*(8/20.4)^(k/8)`；三个光学视图，`u[t]=525/(periodT[3*t+1]*channel_bit_nm)`，共 48 圈 |

例如标准范围的六张输入依次写为 `1R、2G、3B | 4R、5G、6B`；两组三元组的颜色分别来自多张素材，
并非六张原图都能完整还原。标准范围的单张输入在两个三元组重复 RGB；两张 RGB 输入与原默认两图方案使用相同的载波布局。
加宽范围即使输入不超过六张也始终使用九载波；单张输入在三个三元组重复 RGB。
这是固定的通道分配，不分析图片内容，也不保证消除光谱重叠。

灰度来源的 R/G/B 选取均使用同一灰度像素，仍按原始文件格式采样，亮度保持 `g/255`；
RGB 来源先对所选通道双线性插值并取整，再线性化。源项目会先把灰度素材转 RGB 并线性化，本项目保留既有的灰度响应约定。
开启合并后，即使全部输入为灰度，也使用上述彩色三元组、白平衡和字符串载波。
PNG 蒙版忽略 `--color-range`。

### 自定义观看参数

`--viewing viewing.json` 默认按输入图片顺序指定观看方向。
指定 `--color-range` 时，`views` 改为按光学 RGB 三元组排列：`standard` 提供两个视图，`wide` 提供三个，与实际输入数量无关。
JSON 使用 UTF-8：

| 字段 | 默认值与含义 |
|---|---|
| `reference_mm` | `[0, 43]`；盘面上的参考点 `[x, y]`，在此位置设计观看方向 |
| `lamp_mm` | `[350, 0, 1000]`；灯的位置 `[x, y, z]` |
| `eye_mm` | `[0, 0, 500]`；观察眼的位置 `[x, y, z]` |
| `chirp` | 默认 `false`，使用固定名义周期；明确设为 `true` 时按位置补偿周期 |
| `chirp_cell_mm` | 默认 `0.05`；位置补偿网格的目标边长，mm |
| `views` | 与输入图片对应；通道合并时与两个或三个光学三元组对应的对象列表 |
| `views[i].target_u` | 直接指定该视图的正观看分量；存在时不使用其实体灯眼位置和姿态，而在参考点构造对应的规范姿态 |
| `views[i].turn_deg` | 默认 `0`；左右转动角度，正值表示盘片右边缘靠近观察者 |
| `views[i].tilt_deg` | 默认 `0`；上下倾斜角度，正值表示盘片上边缘远离观察者 |
| `views[i].rotate_deg` | 默认 `0`；盘片在自身平面内顺时针旋转的角度 |
| `views[i].eye_mm`、`views[i].lamp_mm` | 为该视图覆盖全局眼睛或灯的位置 |

位置单位为毫米，角度单位为度。盘心为原点，`x` 向右、`y` 向上、`z` 朝观察者；
眼睛与灯都在盘片正面。程序按 `Rz(rotate) × Rx(tilt) × Ry(turn)` 变换灯、眼位置向量，
参考点在计算中保持不动。这些姿态参数用于观看设计，不平移或旋转输入图片的像素。

以参考点 `p=(x,y,0)` 到灯、眼的单位向量分别为 `l`、`e`，轨道切向为
`t=(y,-x,0)/sqrt(x²+y²)`，则 `u=abs((l+e)·t)`。该图的目标周期为：

```text
periodT = wavelengthNm / (channel_bit_nm × u)
```

灰度使用 550 nm。RGB 延续默认 colorflip 第一组三周期对应的波长，约为 614、535、466 nm。
通道合并的六载波使用相同 RGB 波长；宽九载波使用 `[525*q, 525, 525/q]` nm，其中 `q=(20.4/8)^(1/8)`，灰度来源也按其光学 R/G/B 位置设计周期。
程序使用 NumPy 动态合成每个载波的 91 字节串，不把所需周期量化到默认资源目录。
灰度在相同轨道份额下按目标光谱的 Y 响应平衡亮度；含彩色时重新计算 LED 光谱下的 D65 白平衡、
各平面圈数及剩余增益。按图片模式选择采样、原始 `g/255` 响应及 RGB 线性化规则保持不变。

自定义模式的所有载波，包括单张、两张灰度，均使用同步帧重启、填充及尾部裁剪。
因此，即使请求的周期接近默认 `92/B9` 周期，也不要求与默认单字节方案输出相同。

例如，两张灰度图在指定灯、眼位置下分别设计为左右转动 −2°、+2° 观看。保存为 `viewing-gray.json`：

```json
{
  "reference_mm": [0, 43],
  "lamp_mm": [350, 0, 1000],
  "eye_mm": [0, 0, 500],
  "views": [
    {"turn_deg": -2},
    {"turn_deg": 2}
  ]
}
```

```powershell
python dvd_image.py -i gray1.png gray2.png -o turning.iso -c my-disc.json --viewing viewing-gray.json
```

改为俯仰切换时，可设置 `reference_mm` 为 `[43, 0]`、`lamp_mm` 为 `[0, 350, 1000]`，
将两个视图的角度改为 `tilt_deg: -2` 和 `tilt_deg: 2`。

也可直接指定观看分量，不填写灯、眼和姿态。以下 `viewing-mixed.json` 对应一张灰度图和一张彩色图：

```json
{

    {"target_u": 0.27},
    {"target_u": 0.40}
  ]
}
```

```powershell

```

### 位置周期补偿（chirp）

字符串载波依据盘面各处的轨道切向、眼睛和灯的位置改变周期，尽量维持参考点设计的显色波长。
名义周期为 `P0`、参考观看分量为 `u_ref` 时，当地目标周期为：

```text
P(x,y) = P0 × abs(u_ref) / abs(u(x,y))
```

该计算只依赖物理位置与观看几何，不检查图片内容。周期补偿默认关闭：不指定 `--viewing` 时使用固定名义载波，
提供观看 JSON 但省略 `chirp` 时也不准备周期变体。只有明确设置 `"chirp": true` 才启用补偿，
适用于自定义观看的字符串载波，包括单张或两张灰度；默认 `92/B9` 单字节方案保持不变。

例如，在 133.3 nm 通道位长度下，为两张彩色图片保留默认的参考观看分量并启用补偿，可在 `--viewing` 指向的 JSON 中填写：

```json
{
  "chirp": true,
  "views": [
    {"target_u": 0.288},
    {"target_u": 0.4365263711549947}
  ]
}
```

实体几何视图使用已经过转动、倾斜和盘内旋转的实际灯、眼位置。
直接指定 `target_u` 时只有参考点的观看分量，不能唯一决定全盘几何，因此采用明确的对称规范姿态：

```text
p = (reference_x, reference_y, 0)
t = (reference_y, -reference_x, 0) / radius
d = (u/2) × t + sqrt(1 - (u/2)²) × (0, 0, 1)
eye  = p + 500  × d
lamp = p + 1000 × d
```

其参考点观看分量恰为目标 `u`；默认参考点为 `[0, 43]`。
实际使用的灯眼位置会写入参数 JSON。需要指定真实布置时，提供实体几何字段，不使用 `target_u` 覆盖。

补偿网格覆盖完整盘面外径，边数为 `ceil(2 × outer_radius_mm / chirp_cell_mm)`，
实际单元边长为外径除以边数。每个载波平面的每个单元保存一个周期变体编号，不保存整幅浮点配方。
周期按 `1.005` 的对数步长量化，名义周期保留精确值，其余变体吸附到共享周期网格；
该网格为 `6.4 × 1.005^j`，共 248 个周期，最长约 21.94T。名义周期及实际需要的变体只合成一次。

局部周期受约 **6.4–22T** 的可写范围限制，超出时使用相应边界周期；`u=0` 等无法提供有限周期解的位置使用最长周期。
因此补偿在可实现范围内改善显色，不保证同一姿态下整盘所有区域都同时同色，也不消除视图光谱重叠。
名义亮度增益与白平衡仍以参考点的载波响应计算，局部周期变体的亮度可能不同。

新合成的字节串、裁剪表及本次位置索引只保存在进程内存中，不写磁盘缓存。
整盘可能需要上百个不同周期，新进程首次准备可能需要数分钟；共享网格及进程内复用减少重复合成。
启用补偿后的周期变体准备进度在同一行原地刷新，显示完成比例、已完成／总周期数、处理速度和预计剩余时间，完成后换行。
各参数限制见下方输入约定，由使用者保证。

### 观看与资源占用

未合并的默认方案中，多图输入顺序决定各图对应的载波和观看次序，不对应固定的几度倾角；
自定义方案以指定的参考点及观看参数设计方向。实际显现方向随灯、观察位置和盘面区域而变。
用较小的明亮光源，缓慢转动或倾斜盘片寻找各帧。整盘不同方位的轨道朝向不同，通常需要转动盘片查看不同区域。
灰度图实物也会带有衍射颜色，彩色只在设计方向附近显色，倾斜途中会变色。
多张完整彩色图的 RGB 光谱带可能重叠，因此相邻方向会串色、串影；完整保留三个通道不代表各视图完全隔离。

原图以 8 位通道保存，编码时查表转换亮度，不建立整图浮点配方。
图像字段约占 `载波平面数 × 8192²` 字节：默认单张灰度约 64 MiB、单张彩色约 192 MiB，
8 张灰度约 512 MiB、8 张彩色约 1.5 GiB，另加图片解码和输出批次内存。
启用补偿时，位置变体图另占 `载波平面数 × 网格边数²` 字节；58 mm 外半径、0.05 mm 网格时每平面约 5.1 MiB，
8 张完整 RGB 的 24 个平面约 123 MiB，准备时还会使用临时几何数组。
通道合并的六平面约占 384 MiB，九平面约占 576 MiB，另加解码临时内存，启用补偿时再加周期变体图。
未合并的单张 `uint8` 灰度准备接口对原始数组建立视图，不复制整张图。
`ISO路径.json` 记录本次使用的盘片配置、源图、通道、排程、载波周期及增益。

## 文件系统与布局

提供目录后，ISO 包含可挂载的只读 **UDF 2.01** 文件系统，保留子目录和中日韩 Unicode 名称，
支持空文件及空目录。源目录的内容直接位于 ISO 根目录。提供空目录也会生成文件系统；
未提供目录时，输出纯绘图镜像，无可挂载文件系统。

```text
inner：盘首元数据 → 目录与文件 → 对齐填充 → 绘图 → 盘尾备份元数据
outer：盘首元数据 → 对齐填充 → 绘图 → 目录与文件 → 盘尾备份元数据
```

`-p` 控制整个目录与文件分区的位置，盘首和盘尾保留 UDF 元数据。
绘图区按 32 扇区对齐，可供编码器逐个 16 扇区块写入；文件及其保留区不参与绘图。
图片始终按完整盘片几何投影，不会拉伸到剩余区域。

逻辑卷标可完整保存 32 个英文或常用中日韩字符；字段上限为 126 个单字节字符或 63 个双字节字符，超出截断。
文件名最多 254 个单字节或 127 个双字节字符，支持 Unicode BMP，包括常用中日韩文字；
不支持表情等补充平面字符或字节序标记，不会将名称替换为下划线。
单文件可超过 4 GiB，实际受可用容量限制。

- 随盘目录是普通文件和目录组成的有限树，不含符号链接、junction、重解析点或特殊设备；生成期间保持全部源文件和目录不变。

### JSON 与物理参数

- 顶层为 JSON 对象，字段不重复，只使用配置表中的字段。
- `total_sectors` 为正整数且能被 16 整除；其他数值字段使用 JSON 数字，不使用布尔值或数字字符串。
- 内外半径为有限数，满足 `0 < inner_radius_mm < outer_radius_mm <= 60`，单位 mm；`channel_bit_nm` 为有限正数；`direction` 为 `cw` 或 `ccw`。
- `psn_offset` 为非负整数且能被 16 整除，或者对应的 `0x` 十六进制字符串；`psn_offset + total_sectors - 1 <= 0xFFFFFF`。
- 几何参数均为有限数，起始角度换算为弧度后仍为有限数。
- 总轨长 `L = total_sectors * 38688 * channel_bit_nm * 1e-6`（mm）大于内外半径差。
- 相对轨距多项式 `1 + c1*x + c2*x² + c3*x³` 在整个 `0 <= x <= 1` 内严格为正，包括区间内部的极小值。

### 观看参数

- 观看配置顶层为 JSON 对象，使用上表字段；所有位置、角度和 `target_u` 为有限数，使用 JSON 数字。
- `reference_mm` 恰含两个坐标；灯、眼位置恰含三个坐标；每项 `views` 为对象，未合并时数量与输入图片数一致，标准合并为两个，加宽合并为三个。
- 参考点半径非零，并位于配置的数据记录区内；使用文件布局或 `bleed` 时，选择实际可绘区域中的参考点。
- 使用实体几何的视图，姿态变换后的灯和眼都在盘片正面，且到参考点的距离非零；计算或直接指定的观看分量满足 `0 < u < 2`。
- `chirp` 为布尔值；`chirp_cell_mm` 为有限正数。直接指定 `target_u` 的规范姿态使用的参考点同样须满足记录区约定。
- 对每个灰度或 RGB 平面，名义请求周期 `periodT` 在 **8–17.24T** 内；`wide` 合并范围允许 **8–20.4T**。以 133.3 nm 通道位为例，未合并灰度约需 `0.2393 <= u <= 0.5158`，标准 RGB 三通道同时满足时约需 `0.2673 <= u <= 0.4365`；加宽范围按其波长公式换算。局部补偿变体可使用约 **6.4–22T** 的可写范围；该范围夹取属于补偿算法，不是输入范围校验。
- 彩色白平衡方程的解均为正数。不同视图选择足够分离的 `u`，避免相同或过近方向造成明显串影；这不保证各视图完全隔离。
- 程序不对上述结构、范围、可实现性或分离程度进行输入校验，由使用者保证。补偿不能实现超出有限周期范围的几何要求，仍不保证整盘在同一姿态同时显示同一帧或同色。

### 容量、UDF 与 Python 接口

- 应用可用比例后，纯绘图镜像至少包含一个 16 扇区块；使用随盘目录时输出至少为 640 个扇区。文件按扇区取整，加上 UDF 元数据、盘尾备份区及对齐空间，仍至少留出 32 个绘图扇区。
- 文件名、卷标遵循上述 UDF 字符及长度约定，每个目录的直接子目录数不超过 65534。
- `workers` 省略或为 `None` 时自动选择线程数；显式指定时使用 1–64 的整数，`batch_blocks` 为 1–128 的整数。
- `generate_iso` 接受单个图片路径或路径序列，使用统一的载波编码流程。
- `generate_iso` 可用关键字 `viewing=None` 传入已读取的观看参数对象；`None` 使用默认载波方案。命令行 `--viewing` 接受 JSON 文件路径。
- `generate_iso`、两个 profile 准备接口省略 `color_range` 时不合并；显式传入 `"standard"` 启用标准合并并固定六平面，`"wide"` 启用加宽合并并固定九平面。默认值 `None` 仅表示未提供范围。返回的 `profile.channel_merge` 记录由范围派生的合并状态。
- `generate_iso` 和两个 profile 准备接口均接受 `no_gain=False`；设为 `True` 后，`profile.gains` 及亮度查表使用的增益全部为 1，原有圈份额和载波准备不变。
- `dvd_multiview.prepare_multiview(paths, viewing=None, channel_bit_nm=133.3, radii_mm=(24,58), color_range=None, no_gain=False)` 接受路径序列：未合并 1–8 个、标准合并 1–6 个、加宽合并 1–9 个；`paths` 以外为关键字参数。
- 已有数组可用 `dvd_multiview.prepare_images(images, source_paths=None, viewing=None, channel_bit_nm=133.3, radii_mm=(24,58), color_range=None, no_gain=False)` 准备 profile，`images` 以外均为关键字参数。`images` 数量遵循相同的三种范围约定，每项为 C 连续布局的 `(8192, 8192)` `bool` 黑白、`(8192, 8192)` `uint8` 灰度或 `(8192, 8192, 3)` `uint8` RGB；可选路径序列与图片数一致。二维 `bool` 选择最近邻并展开为 0/255；二维 `uint8` 灰度和三维 `uint8` RGB 各通道均选择双线性，即使灰度像素仅为 0/255。数组不按像素内容分类，也不接受二值标记覆盖。
- 准备 profile 使用的 `channel_bit_nm`、`radii_mm=(inner_radius_mm, outer_radius_mm)` 与后续 `PreparedKernel` 的盘片配置一致；`generate_iso` 自动传入实际盘片半径。
- `prepare_images` 与文件序列入口共用同一个 profile 构建流程；未合并的单张 `uint8` 灰度对原数组建立视图，不复制整张图片。`bool` 黑白数组需展开为 `uint8` 0/255 像素。
- `dvd_disc.plan_output(options, data_dir=None, file_position="inner", volume_label="DVD_IMAGE", bleed=1)` 返回 `OutputPlan`，统一持有完整几何、输出扇区数、UDF 布局及绘图区。ISO 和蒙版均使用这一计划。
- 高效分批编码先建立 `kernel = dvd_kernel.PreparedKernel(options, plan.geometry, profile)`，随后复用 `kernel.generate_payload(start_block, block_count)`。构造时一次准备几何表、模型指针及 DVD 位置/扰码表，并保留其生命周期。
- 扇区解析使用 `kernel.resolve_sector(codes, variants=None)`；`codes` 仍为载波编号和 `A5` 关闭标记，可选 `variants` 给出每位置的组内变体编号，省略时均使用名义变体 0。业务准备接口位于 `dvd_multiview.py`，原生封装位于 `dvd_kernel.py`。
- `start_block`、`block_count` 为非负整数，整个块范围位于输出可用容量内。`DvdGeometry.positions` 的弧长为有限数，位于 `[0, L]`。
- 直接调用 UDF 写入接口时，按规划顺序写入前缀、绘图区和后缀，使用布局计划中的 LBA。

### 原生数据与载波资源

直接构造 profile 或调用原生接口时，由调用者保证以下布局和数值关系，程序不额外检查：

- 黑白及灰度图片总数为 `Ng`、彩色图片数为 `Nc`，`N = Ng + Nc`。未合并时 `1 <= N <= 8`、载波平面数 `C = Ng + 3*Nc`；标准合并时 `1 <= N <= 6`、`C=6`；加宽合并时 `1 <= N <= 9`、`C=9`。源图模式、路径、各平面所属图片和通道与数组一致；`carrier_frames` 始终记录实际源图索引，合并时光学组由 `plane//3` 给出，`target_u` 和 `viewing_poses` 按光学组排列。
- 数组均为 NumPy C 连续布局：`field` 为 `(C, 8192, 8192)` 的 `uint8`；`levels` 为 `(C, 256)` 的 `float32`，按源图模式选择灰度 `(g/255) × gain` 或线性 RGB 乘增益，值为 `[0, 1]` 内有限数；`no_gain=True` 时所有 `gain` 为 1。合并时 `channel` 为 R/G/B 不改变源图模式。
- 全部变体字符串总数为 `V`。`carrier_bytes` 为 `(V, 91)` 的 `uint8`，`trim` 为 `(V, 92)` 的 `uint8`，按载波组紧凑排列；`variant_offsets` 为 `(C,)` 的 `int64`，记录各组在字节串表中的起点。每组变体 0 为名义串。
- `variant_map` 为 `(C, H, W)` 的 `uint8` 位置索引；未启用补偿时为 `(C, 0, 0)`。`variant_periods` 为 `(V,)` 的 `float64`，记录每个变体的请求周期。各组变体数不超过 256。
- `sampling_modes` 为 `(C,)` 的 `int64`：0 表示彩色双线性，1 表示 1 位黑白格式最近邻，2 表示灰度双线性。模式 0、2 使用相同的插值及最近偶数取整规则；元数据的 `color-bilinear`、`gray-binary-nearest`、`gray-bilinear` 分别对应模式 0、1、2。
- `single_byte_carriers` 仅在未合并、默认的一张或两张全灰度方案中为 `True`，此时各行字节为重复的 `92/B9`；其他方案及自定义观看参数均为 `False`，使用字节串解析。
- `counts` 为 `(C,)` 的正整数 `int64`；`cycle`、`rank` 为 `(slots,)` 的 `int64`，`slots = sum(counts) <= 128`。`cycle` 编号位于 `0..C-1`，各载波出现次数等于 `counts`，对应 `rank` 逐一记录 `0..counts[cycle]-1` 的圈序号。
- `centres` 为 `(32768,)` 的 `int64`，`masks` 为 `(16, 2048)` 的 `uint8`，均为 C 连续布局。位置表由 `PreparedKernel` 初始化并缓存，扰码表由 `dvd_disc.scrambler_masks()` 提供；两者均由会话持有，直接调用 C 时也使用同一 DVD payload 位置与扰码规则。
- `PreparedKernel.resolve_sector` 的 `codes` 输入为 `(2048,)` 数组，值为 `0..C-1` 或填充标记 `0xA5`；可选 `variants` 为同长度的组内变体编号数组。封装打包为 `uint16` 原生 token：`(plane << 8) | variant`，关闭标记为 `0xFFFF`。每次处理完整扇区；数组、查找表及 profile 在并行编码期间持续存活且保持不变。
- 程序始终假定代码与数据资源配套，不保存或比较来源、提交号、资源版本；这些信息仅记录在 [NOTICE.md](NOTICE.md)。
- `multiview-carriers.json` 包含使用中的 1–8 图方案。每个字节串解码后长 91，裁剪表长 92；周期及白平衡权重 `whiteNeed` 为有限正数。
- `efmplus-tables.json` 仅提供动态载波合成所用的 `main` 主编码表，每项为 `[码字, 后继状态]`。

## 与源项目的行为差异

以下仅比较当前保留的实现；源码来源和参考提交见 [NOTICE.md](NOTICE.md)。

| 项目 | DiscImageStudio | 本项目 |
|---|---|---|
| 灰度采样与抖动 | 按图片是否二值选择最近邻或双线性；按阈值或字节位置相关的 tone 抖动选择黑白纹理 | 按文件模式或数组类型选择：1 位黑白最近邻、灰度双线性，不分析像素内容；使用 `(g/255) × gain`、32 级圈门限和 4×4 有序抖动 |
| 完整通道反馈求解 | 提供 Full 局部搜索与 StateControl 状态控制及多 lane／重试等增强 | 未保留；候选搜索需反复执行完整 ECC／EFMPlus／NRZI 编码，计算量大，当前只提供载波直接绘图 |
| ISO 与文件布局 | 支持随盘文件布局、可写容量及外缘预留设置 | 可选 UDF 2.01；`-p` 移动整个目录与文件分区，`-b` 控制输出容量，完整几何和原图映射保持不变 |

|---|---|---|

## 输出与来源

ISO 按有限批次并行采样、按顺序写出，内存不随盘片容量增长。临时输出位于目标目录，成功后发布；
失败或 Ctrl+C 清理本次临时输出。单层 DVD 使用连续螺旋模型，不处理双层盘换层。

轨道几何与扰码参考 DiscImageStudio，按圈复用、RGB 载波及帧衔接参考 DiscDiffractStudio。
本项目将整张 PNG 映射到完整盘心画布，支持按位置微调字符串周期，
不包含参考项目的图层布局、视频导入、深度推断、姿态预览或刻录功能。
